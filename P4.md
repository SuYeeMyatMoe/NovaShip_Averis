## Setup
```bash
cd frontend
cp .env.example .env.local        # NEXT_PUBLIC_API_BASE=http://localhost:8000
npm install
npm run dev                       # http://localhost:3000  (backend must run on :8000)
npm run build                     # must pass before every deploy (type-check included)
```
Backend for you: `cd backend && python -m uvicorn app.main:app --reload --port 8000`. If Docker already holds 3000/8000, run `.\scripts\dev.ps1 stop` or `.\scripts\dev.ps1 frontend` (local Next + Docker API) first — see README §9. In memory mode the API already holds 520 cases; **you do not need Supabase or Gmail to build anything.** When P3 announces "Supabase is up", only `NEXT_PUBLIC_API_BASE` changes (if the API moved); the JSON shapes are identical.

## Gmail switch impact on P4

There is **no provider-specific frontend rewrite** for the Gmail change. The frontend continues to consume the same case, email, attachment, draft, share and audit JSON contracts.

What changes for P4:
- The browser E2E proof should include one case that originated from a real Gmail message after P3 runs `POST /connectors/poll`.
- The case must render exactly like a webhook/bundle case: Original Email, attachments, seven-field comparison, evidence, draft, collaboration and audit all use the existing UI.
- P4 does not handle Google OAuth and must never receive `GMAIL_CLIENT_SECRET` or `GMAIL_REFRESH_TOKEN`. Those remain backend-only.
- When P3 enables real Gmail sending, P4 verifies the existing approval/confirmation UI and resulting audit/status transitions; no Gmail-specific button or credential screen is required.
- If the connector is unavailable, the UI should surface the existing API error state rather than implementing provider logic in React.

E2E provider boundary:

```text
Gmail mailbox
    ↓ P3 polls/normalizes
FastAPI + Supabase
    ↓ existing API contracts
P4 frontend
```

## Dashboard focus (what judges look at first)
1. Tiles answer "how much work is there" in one glance: Action required, Mismatches, Waiting for documents, Human review, Security flagged.
2. The seven-field strip under the tiles shows mismatches by field (Container Count 19, Port of Discharge 13 ...). Clicking goes to `/verification`.
3. Table rows: mismatch badge in red, "No mismatch" in green, "Review" in amber; SI / BL dots; confidence bar; status badge; actions Open, Compare, Ask AI, Share, Draft, Audit.
4. Filters map 1:1 to `GET /cases` query params (status, priority, intent, mismatch, security, assigned, shared, sender, min confidence, date from/to, sort, free text).

## Where the seven fields are on screen
- Case Overview and the Seven-Field Comparison tab: `SevenFieldCard` (`components/comparison.tsx`). Never hidden; the "show matches" toggle only dims matches.
- Evidence tab: `EvidencePanel`, per field, SI and BL snippet with the label that was resolved.
- `/verification`: statistics per field and a table of every case for the selected field and result.
- Inbox strip: mismatch count per field.
- Draft text quotes the SI and BL values for each mismatched field.

## Vercel deployment
1. vercel.com -> Add New Project -> import the repo -> **Root Directory: `frontend`** -> Framework Next.js (auto).
2. Environment Variables: `NEXT_PUBLIC_API_BASE` = the API URL from P3 (Cloudflare tunnel or container, e.g. `https://api.yourdomain.com`). No other keys belong in Vercel.
3. Deploy. Send the `https://<project>.vercel.app` URL to P3 so it is added to backend `CORS_ORIGINS`.
4. Any later change of `NEXT_PUBLIC_API_BASE` needs a redeploy (it is compiled into the bundle).
5. Preview deploys per branch are free; production on Sunday evening.

## If something is wrong
| Symptom | Look at | Fix |
|---|---|---|
| Header says API offline | `NEXT_PUBLIC_API_BASE`, CORS | rebuild after changing the variable; P3 adds the Vercel origin |
| 401 / 403 toasts | acting user | Operations cannot approve or notify external; pick a Supervisor |
| Seven-field card says Not compared yet | `review_reason` | expected for missing or unreadable documents; upload on Attachments |
| Evidence tab empty | `si_evidence.document_id` must equal an attachment id | ask P1 |
| Recipient greyed out | `allowed=false` | role lacks permission or party is not approved (by design) |
| Build type error | `lib/api.ts` types | add optional fields, never remove |
