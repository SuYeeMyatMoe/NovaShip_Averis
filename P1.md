## Gmail switch impact on P1

The email-provider change does **not** change P1's AI implementation. Classification, document detection, extraction, evidence, the deterministic seven-field comparator, summaries, drafts and LangGraph nodes continue to receive the same normalized email/case contracts.

What changes for P1:
- The real-provider acceptance test now starts from a **Gmail message**, not Outlook/Microsoft Graph.
- P3 owns Google OAuth, mailbox polling, MIME decoding and attachment download. By the time P1 code runs, Gmail has already been normalized into the existing `InboundMessage` / pipeline input.
- P1 must validate that a real Gmail message containing an SI and Draft BL produces the same extraction/evidence/comparison behaviour as fixture or webhook ingestion.
- Pay particular attention to Gmail HTML-body normalization, MIME attachments, filenames and evidence document IDs. Provider-specific parsing bugs belong to P3; extraction/comparison bugs belong to P1.
- P1 does **not** manage `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`, `GMAIL_REFRESH_TOKEN`, OAuth consent or outbound sending.

Provider boundary:

```text
Gmail API (P3)
    ↓
normalized InboundMessage + attachment bytes
    ↓
Pipeline / classifiers / extractor / comparator / agent (P1)
```

## If something is wrong
| Symptom | Look at | Fix |
|---|---|---|
| Field MISSING but visible in the document | `extractor._collect_candidates` | add label to `LABEL_SYNONYMS` |
| Container number parsed as weight | `normalizer.normalize_weight_kg` | keep the letter/digit refusal |
| Two different legal names marked MATCH | `normalizer.normalize_party` | do not add fuzzy matching (policy decision) |
| Formatting-only difference is a MISMATCH | `normalize_port / normalize_text` | extend rule + add a test |
| LLM summary mentions a field the comparator did not flag | guards in `summary_draft.polish_with_llm`, `assistant._llm_answer` | guards already reject; never weaken |
| Graph does not pause | `nodes.summarize_and_draft` -> `needs_human` | mismatch or review field must be present |
