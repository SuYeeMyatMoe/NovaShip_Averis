# P3 — Backend / Supabase / Integration handoff

P3 backend implementation is wrapped for team deployment. The backend owns persistence; AI modules do not access Supabase directly.

## Completed

- FastAPI + RBAC + audit + idempotent ingestion
- Supabase repository and hardened live database
- private Supabase Storage path
- real Gmail inbound connector
- replay/duplicate protection
- LangGraph Postgres checkpoints with restart persistence
- Supabase pgvector RAG with pre-ranking case/source scoping
- 768-dimensional embeddings
- 1,420 vector chunks indexed
- 104 backend tests passed
- outbound Gmail simulation-only
- local `.env` untracked

Validated pre-deployment baseline: `387ccc7500625017beaa7148ee7d17a340ab091a`.

## Final deployment architecture

```text
Vercel
├── frontend/  Next.js
└── backend/   FastAPI
      ↓
Supabase DB + Storage + pgvector + Postgres checkpoints
      ↓
Gmail API
```

Root `vercel.json` routes `/api/*` to FastAPI and all other paths to Next.js. Cloudflare is not part of the final plan.

## Gmail

```text
EMAIL_PROVIDER=gmail
EMAIL_SEND_MODE=simulate
```

Real inbound Gmail is validated. Keep outbound simulation-only until the team deliberately performs deployed send validation.

## Authentication

The validated profile is `AUTH_MODE=demo`.

Demo auth is appropriate for a controlled hackathon demonstration, not unrestricted production. It includes normal signed sessions plus the `X-User-Id` shortcut and shared demo credentials.

See [docs/DEMO_AND_LIVE_MODES.md](docs/DEMO_AND_LIVE_MODES.md) for the exact behavior and production transition.
